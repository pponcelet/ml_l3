Règles d'association — Apriori

Identifier les ensembles de produits fréquents dans une base de transactions et en déduire des règles d’association.

1. Principe

Une transaction représente ici un panier ; un item désigne un produit. Un itemset est un ensemble de produits, par exemple {Pain, Beurre}. Il est fréquent lorsque son support atteint le seuil choisi.

Une règle telle que {Pain} ⇒ {Beurre} signifie que les paniers contenant du pain contiennent souvent aussi du beurre. Elle ne décrit ni un lien causal ni l'ordre des achats.

2. Algorithme général

Le support d'un itemset X est la proportion de transactions qui contiennent tous ses produits. Pour obtenir les itemsets fréquents, Apriori procède par niveaux : il construit des candidats de taille k, compte leur support, puis ne conserve que ceux qui satisfont le seuil.

Ck — candidats

Combinaisons de k produits susceptibles d'être fréquentes ; les candidats élagués ne sont pas comptés.

Lk — itemsets fréquents

Candidats de taille k dont le support atteint le minimum ; ils serviront à construire le niveau suivant.

  1. Comptez les supports des produits individuels et obtenez L1.
  2. Pour k = 2, 3, …, générez les candidats Ck à partir de Lk−1.
  3. Éliminez les candidats dont au moins un sous-ensemble de taille k−1 n'est pas fréquent.
  4. Comptez les supports des candidats conservés et formez Lk.
  5. Arrêtez lorsqu'il n'y a plus de candidats ou d'itemsets fréquents.
L1 = itemsets fréquents de taille 1
Pour k = 2, 3, ... tant que L(k-1) est non vide :
    Ck = générer les candidats à partir de L(k-1)
    retirer les candidats avec un sous-itemset non fréquent
    compter le support des candidats restants
    Lk = {X dans Ck : support(X) ≥ minsup}
Retourner tous les Lk

Pourquoi peut-on élaguer ? Si {Pain, Lait} n'est pas fréquent, aucun ensemble contenant à la fois Pain et Lait ne peut être fréquent : son support ne peut pas être supérieur.

4. Des itemsets fréquents aux règles

Une fois les itemsets fréquents obtenus, nous considérons chaque décomposition d'un itemset en deux parties non vides et disjointes X et Y pour produire une règle X ⇒ Y. La confiance minimale permet de sélectionner les règles retenues.

5. Avantages et limites

Avantages

  • Étapes de génération, élagage et comptage faciles à suivre.
  • Recherche complète des itemsets satisfaisant le seuil minimal.
  • Résultats interprétables à partir du tableau de transactions.

Limites

  • Nombre de candidats et de règles parfois très élevé.
  • Plusieurs parcours de la base peuvent être nécessaires.
  • Choix des seuils délicat ; nombreuses règles potentiellement redondantes.

6. Questions pour réfléchir

1. Retirez le beurre de deux paniers qui contiennent également du pain. Quels supports et quelles règles sont modifiés ?

Éléments de réponse

Les supports de tous les itemsets qui contiennent du beurre diminuent s'ils étaient présents dans les paniers modifiés. Le support de {Pain} ne change pas. Les confiances des règles impliquant ces itemsets peuvent changer : une règle peut passer sous le seuil retenu.

2. Augmentez le support minimal. Comment évolue le nombre d’itemsets fréquents et pourquoi ?

Voir la réponse

Le nombre d'itemsets fréquents ne peut pas augmenter quand le support minimal augmente : seuls les ensembles qui dépassent encore le nouveau seuil sont conservés. Les candidats issus d'ensembles éliminés sont également élagués.

3. Comparez les règles {Pain} ⇒ {Beurre} et {Beurre} ⇒ {Pain}. Ont-elles nécessairement la même confiance ?

Voir la réponse

Non. Les deux règles ont le même support conjoint, mais pas le même dénominateur : conf(Pain ⇒ Beurre) = supp(Pain, Beurre) / supp(Pain), tandis que conf(Beurre ⇒ Pain) = supp(Pain, Beurre) / supp(Beurre). Les confiances diffèrent généralement.

4. Une confiance élevée signifie-t-elle que l’achat d’un produit provoque celui d’un autre ?

Voir la réponse

Non. Une confiance élevée traduit une cooccurrence conditionnelle, pas une causalité. D'autres facteurs peuvent expliquer les achats ; le lift, les fréquences de base et le contexte aident à interpréter la relation.

Pour aller plus loin — formalisation mathématique

Considérons les 12 transactions initiales du tableau pour calculer les différentes mesures.

1. Représenter la base de transactions

Soit I l’ensemble des produits et D = (T1, …, Tn) une base de n transactions, où Ti ⊆ I.

I = {Pain, Beurre, Lait, Œufs, Confiture},   n = 12

Par exemple, T1 = {Pain, Beurre, Lait} et T2 = {Pain, Beurre}. L’ensemble X = {Pain, Beurre} est un itemset. Il est présent dans une transaction lorsque X ⊆ Ti.

2. Calculer le support d’un itemset

On commence par compter le nombre de transactions contenant un itemset :

N(X) = |{Ti ∈ D : X ⊆ Ti}|

Le support relatif correspond à la proportion de transactions concernées :

supp(X) = N(X) / n

Dans les 12 paniers initiaux, le pain apparaît 9 fois, le beurre 8 fois, et les deux produits apparaissent ensemble 8 fois :

Itemset XNombre N(X)Support supp(X)
{Pain}99 / 12 = 75 %
{Beurre}88 / 12 ≈ 66,7 %
{Pain, Beurre}88 / 12 ≈ 66,7 %
{Pain, Lait}22 / 12 ≈ 16,7 %

Si le support minimal est fixé à 3 transactions sur 12 (soit 25 %), {Pain, Beurre} est fréquent, mais {Pain, Lait} ne l’est pas.

3. Comprendre la propriété utilisée par Apriori

Si X ⊆ Y, toute transaction contenant Y contient aussi X. Donc :

X ⊆ Y   ⇒   supp(Y) ≤ supp(X)

Par exemple, X = {Pain, Lait} apparaît dans 2 paniers, tandis que Y = {Pain, Beurre, Lait} apparaît dans 1 seul panier :

supp(Y) = 1 / 12 ≤ 2 / 12 = supp(X)

Puisque {Pain, Lait} n’atteint pas le seuil de 3 paniers, aucun ensemble plus grand qui le contient ne peut être fréquent. Apriori peut donc éliminer de tels candidats sans calculer leur support. C’est la propriété d’antimonotonie du support.

4. Construire et mesurer une règle d’association

À partir d’un itemset fréquent, on construit une règle X ⇒ Y avec X ∩ Y = ∅ et X ≠ ∅, Y ≠ ∅. Dans notre exemple :

{Pain} ⇒ {Beurre}

Le support de la règle est celui de l’ensemble des produits présents à gauche et à droite :

supp(X ⇒ Y) = supp(X ∪ Y) = 8 / 12 ≈ 66,7 %

La confiance mesure la proportion de paniers contenant X qui contiennent également Y :

conf(X ⇒ Y) = supp(X ∪ Y) / supp(X)
= (8 / 12) / (9 / 12) = 8 / 9 ≈ 88,9 %

Le lift compare cette confiance à la fréquence de Y pris isolément :

lift(X ⇒ Y) = conf(X ⇒ Y) / supp(Y)
= (8 / 9) / (8 / 12) = 4 / 3 ≈ 1,33

Le lift est supérieur à 1 : pain et beurre sont associés positivement dans ces transactions, relativement à ce que l’on attendrait sous indépendance. Cela ne prouve pas une relation causale.

Le sens de la règle est important : la règle inverse {Beurre} ⇒ {Pain} a une confiance de 8 / 8 = 100 %, même si le support et le lift sont identiques.

5. Pourquoi Apriori est-il utile ?

Avec m produits, il existe 2m − 1 itemsets non vides. Pour les 5 produits de notre base, cela représente 25 − 1 = 31 itemsets potentiels. Apriori exploite l’antimonotonie pour éviter d’examiner certains candidats, même si le nombre d’itemsets fréquents peut rester très élevé.
