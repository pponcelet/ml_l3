FONDAMENTAUX

Du problème à l'évaluation

Relier la définition du problème, la préparation des données, l'apprentissage et l'évaluation finale dans une même démarche.

1. Définir le problème

Nous souhaitons prédire si un abonné renouvellera son abonnement à partir de son nombre de visites et de son canal de contact (site ou boutique). La cible possède deux valeurs : « Oui » et « Non ». Il s'agit d'une classification supervisée binaire.

Avant de choisir un algorithme, il faut identifier la cible, les variables disponibles au moment de la prédiction et la façon dont on mesurera les erreurs.

2. Examiner et préparer les données

Voici quelques observations :

ObservationVisitesCanalRenouvellement
A1SiteNon
B3BoutiqueNon
C4SiteOui
D6BoutiqueOui

Le nombre de visites est numérique. Le canal est catégoriel nominal : une transformation telle que l'encodage one-hot permet de l'utiliser dans de nombreux modèles. Les éventuelles valeurs manquantes sont traitées en estimant les paramètres d'imputation sur l'entraînement seulement.

Il faut aussi vérifier qu'une même personne n'apparaît pas dans plusieurs ensembles et qu'aucune variable ne révèle après coup le renouvellement.

3. Séparer les données avant l'apprentissage

Nous utilisons ici 16 observations : huit pour l'entraînement, quatre pour la validation et quatre pour le test. Un exemple de répartition est présenté ci-dessous ; la répartition est décidée avant le choix des paramètres.

EnsembleNombre de visitesCible réelle
Entraînement1, 2, 3, 3, 4, 5, 6, 7Non, Non, Oui, Non, Oui, Oui, Oui, Oui
Validation2, 4, 5, 6Non, Oui, Non, Oui
Test1, 3, 4, 6Non, Non, Oui, Non

Le jeu de test reste à l'écart des décisions de préparation et du choix du modèle.

4. Apprendre et choisir un modèle

Commençons par une règle de classification simple, portant uniquement sur les visites : « prédire Oui si le nombre de visites est au moins égal à un seuil ». Nous comparons deux seuils sur la validation.

RèglePrédictions sur les quatre observations de validationExactitude
Visites ≥ 4Non, Oui, Oui, Oui3/4 = 75 %
Visites ≥ 5Non, Non, Oui, Oui2/4 = 50 %

Nous choisissons le seuil 4 sur la validation, puis nous le figeons. Pour un apprentissage réel, ce type de seuil pourrait être appris par un arbre de décision ; le principe de sélection sur la validation reste identique.

5. Comparer à une référence et tester

Une référence consiste à prédire systématiquement la classe majoritaire de l'entraînement. Ici, cinq observations d'entraînement sur huit sont positives : la référence prédit donc toujours « Oui ». Sur le test, elle obtient 1 bonne prédiction sur 4, soit 25 %.

La règle retenue « visites ≥ 4 » prédit Non, Non, Oui, Oui sur le test, contre les valeurs réelles Non, Non, Oui, Non : elle obtient 3/4 = 75 % d'exactitude.

Le modèle surpasse cette référence sur ces quatre observations, mais cet échantillon est trop petit pour conclure à une performance générale fiable. Il faut examiner les types d'erreurs, utiliser suffisamment de données et, selon le contexte, tenir compte du déséquilibre des classes.

6. Interpréter et généraliser

Une bonne performance mesurée ne garantit pas que le modèle restera pertinent si les utilisateurs, les habitudes ou la collecte des données changent. Il faut examiner la représentativité des observations, les groupes éventuellement sous-représentés et les conséquences d'une erreur.

Retenez l'ordre essentiel : définir le problème, préparer les données sans fuite, entraîner, choisir sur la validation, comparer à une référence et évaluer une dernière fois sur le test.

7. Questions pour réfléchir

1. Pourquoi le canal de contact doit-il être transformé pour certains algorithmes ?

Voir la réponse

Une catégorie telle que « Site » ou « Boutique » n'est pas une mesure numérique. Le one-hot encoding crée des variables binaires sans imposer d'ordre artificiel entre les catégories ; la transformation est définie sur les données d'entraînement.

2. Pourquoi ne peut-on pas modifier le seuil après avoir consulté le résultat de test ?

Voir la réponse

Le test commencerait à guider le choix du modèle et ne serait plus indépendant. Il faut réserver les réglages à la validation, puis utiliser le test une fois le choix fixé.

3. Pourquoi la comparaison à une référence est-elle utile ?

Éléments de réponse

Un score isolé ne révèle pas si le modèle apporte réellement une amélioration. Une prédiction constante fondée sur la classe majoritaire fournit un premier point de comparaison ; il faut ensuite considérer les métriques adaptées et l'incertitude liée à la taille de l'échantillon.

Pour aller plus loin — formalisation mathématique

Les trois ensembles

On note Dent, Dval et Dtest les trois ensembles disjoints. Pour un classifieur fθ défini par des paramètres θ, les hyperparamètres sont choisis en maximisant le score de validation.

θ* = arg maxθ Scoreval(fθ)

Dans l'exemple, le seuil fait partie des choix : l'exactitude sur la validation est de 75 % pour 4 et de 50 % pour 5. Nous retenons donc le seuil 4 parmi ces deux candidats.

Évaluation finale

Une fois la règle fixée, la performance sur le test est calculée sans autre réglage :

Exactitudetest = Nombre de prédictions correctes / Nombre d'observations = 3/4 = 0,75

Cette estimation dépend de la taille du test et de sa représentativité. Elle ne doit pas être interprétée comme une garantie sur toutes les observations futures.
